How it works

Every answer on this site comes with the passages it was built from and the search evidence that found them. Here is the whole path from a document to a cited answer.

  1. Documents are cut into passages

    Each document is split into passages of about 300 words that overlap by 50, so a sentence near a boundary is never lost. Three public-domain documents are preloaded; a file you upload is cut the same way, kept only in memory for your session, and deleted after an hour.

  2. Every passage is indexed twice

    Once as words, in an SQLite FTS5 index ranked by BM25, and once as a 384-number embedding from {{ about.embed_model }}, stored with sqlite-vec. Both live in one database file; no external service is involved.

  3. Your question runs against both

    Keyword search and vector search each return twenty candidates. The two ranked lists are fused by reciprocal rank (each passage scores the sum of 1 / (60 + rank) across the lists) and the top five passages go on. The mode switch lets you use either list on its own.

  4. The answer is written from those passages only

    {% if about.generation_mode == 'groq' and about.model %}

    {{ about.model }}, running on Groq, is shown the five numbered passages and told to answer from them alone, citing as [n], and to say "The documents do not say" when they do not. If the model cannot be reached, the site falls back to showing the best-supported passage instead.

    {% else %}

    This deployment has no generation key, so the site shows the best-supported passage as the answer, with the words from your question highlighted. With a Groq key set, a Llama model writes the answer from the five passages and cites them as [n].

    {% endif %}
